# Adaptive Profiles V2 migration

## Current V1

The original deployment serves the vanilla `site/` bundle and a Worker API. GitHub remains the canonical source: `data/games`, `data/devices`, optional `data/profiles`, and the deterministic `generated/index.json` read model. Released QCM clients may use the old repository and V1 index directly.

## V2 foundation

The application now builds a static React/TypeScript/Vite bundle in `web/dist/`. Cloudflare Wrangler serves those assets and runs the Worker first for `/api/*`. `packages/registry-types` is framework-free; `profile-viewer` owns the visualization seam and currently reports when an unmapped CSV cannot be rendered safely; `device-visualizer` owns generic device presentation.

The V2 index is `generated/index.v2.json` with `targets`, `devices`, and `profiles`. The legacy `generated/index.json` is still generated byte-for-byte from the V1 model and remains the compatibility read model.

## Registry split

`registry-export/` is a complete local export prepared for `Bbrizly/Adaptive-Profiles-Registry`. It is not a production cutover. The Worker reads `REGISTRY_GITHUB_OWNER`, `REGISTRY_GITHUB_REPO`, and `REGISTRY_GITHUB_BRANCH`, falling back to the existing `GITHUB_*` variables. Keep those values pointed at `Bbrizly/Adaptive-Profiles` until QCM is released with the new source and the replacement repository has a writable fine-grained token.

The public registry repository should eventually contain `targets/`, `devices/`, `profiles/`, both generated indexes, validation tools, CI, and `CODEOWNERS`. Do not make this application repository private until released QCM versions no longer depend on its raw paths.

## API compatibility

All existing `/api/v1` routes are preserved. `/api/v2` adds generic targets, game/software projections, filters, search, CSV links, generic submissions, and stale revision/SHA proposal validation. V1 profile data is projected into V2 without changing existing IDs.

## Deployment and rollback

Run `npm run check`, then `npm run deploy:preview`. Preview uses the `adaptive-profiles-preview` Wrangler environment and the old registry by default. Smoke test both API versions and nested SPA routes before production. Production remains `adaptive-profiles`; `npm run deploy` is intentionally manual. Roll back by redeploying the last known-good Worker commit/version and restoring the prior registry variables.

## Compatibility gate

QCM source could not be inspected in this environment: no local checkout is available and the configured `gh` credential is invalid. The repository cutover is therefore intentionally blocked. Inspect QCM's generated-index URL, CSV path, unknown-field handling, and fallback behavior before changing the registry variables.
